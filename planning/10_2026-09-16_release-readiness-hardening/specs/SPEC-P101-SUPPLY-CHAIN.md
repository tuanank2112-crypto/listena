# P101 — Supply-chain and legacy runtime cleanup

## Objective

Remove unused Kokoro/HuggingFace code from the deployable graph, patch the supported Next/Cloudflare toolchain without a major migration, and leave an auditable disposition for every high/critical advisory.

## Required changes

1. Prove no runtime import reaches `src/core/tts/kokoro-client.ts` or `kokoro.worker.ts`; then remove those two unused files, `scripts/tts-prebuild.ts` Kokoro work, the `tts:prebuild` script if no supported VieNeu-only use remains, and Kokoro-only environment entries/docs.
2. Remove direct production dependencies `kokoro-js` and `@huggingface/transformers`. CẤM keep them as dev dependencies solely to silence a diff.
3. Update `next` and `eslint-config-next` together to the reviewed 16.3.x patch whose resolved `sharp` is `>=0.35.4`. Do not move to Next 17 in this WP.
4. Update Wrangler only within the reviewed 4.x line if Worker rollback build/test remains green. Cloudflare artifacts remain rollback assets until Plan07 closes.
5. Keep Prisma client/CLI/adapters on one compatible 6.19.x version in this WP. The `deepmerge-ts` CLI advisory requires a documented build-time exposure disposition; do not force Prisma 7/8 or an untested override.
6. Run `npm ci` from the resulting lockfile. `package-lock.json` must be generated by npm, not hand-edited.

## Dependency acceptance contract

```ts
type AdvisoryDisposition = {
  package: string;
  advisory: string;
  severity: "high" | "critical";
  path: string[];
  exposure: "production-runtime" | "build-tool" | "historical-rollback-tool";
  resolution: "removed" | "upgraded" | "accepted-temporarily";
  owner: string;
  expiresOn?: string;
  evidence: string;
};
```

The artifact is stored in Plan10 acceptance evidence, not by suppressing npm output. `accepted-temporarily` is forbidden for a reachable production-runtime high/critical advisory. A build/rollback exception needs owner, expiry and proof it is absent from the Vercel runtime bundle.

## Forbidden zone

- CẤM `npm audit fix --force`, arbitrary `overrides`, major Prisma/React/TypeScript/Zod/Auth.js updates, or re-enabling Kokoro runtime.
- CẤM delete OpenNext/Wrangler/Worker files while Plan07 rollback remains open.
- CẤM claim that an unused source file is harmless while its vulnerable package is still a production dependency.
- CẤM use `npm outdated` alone as evidence of compatibility or security.

## Errors and worker behavior

| Failure | Required action |
|---|---|
| Lockfile resolves vulnerable `sharp` | stop; inspect exact dependency path; do not waive runtime exposure |
| Next patch breaks build/routes | revert only P101 package changes through a normal patch; report blocked, do not downgrade unrelated code |
| Wrangler patch breaks rollback build | keep prior pinned version with dated rollback-tool exception; Plan07 owner decides later |
| Prisma advisory has no safe 6.x fix | record build-tool exception and separate major-migration task; do not force major here |
| Removed file has a real import | stop removal, map runtime use and revise contract through root |

## Acceptance evidence

- `npm ls kokoro-js @huggingface/transformers sharp prisma wrangler --all` shows Kokoro/HF absent and safe Next sharp resolution.
- `npm audit --omit=dev --json` has zero production-runtime high/critical findings; any CLI/rollback finding has a complete disposition.
- Unit/type/lint/build/E2E pass; `npm run build` route inventory stays equivalent.
- Static scan finds no Kokoro model env/comment/import except historical docs explicitly labelled historical.
